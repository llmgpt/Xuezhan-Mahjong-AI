# 独立策略评测 V2：开发记录与运行方法

> 2026-10-18。本文保存初始策略开发结果和暗杠诊断。后续真实公开历史、高级公有参考及配对续局已实现，当前状态见 [V3 记录](INDEPENDENT_BENCHMARK_V3.md)。尚无新的正式留出结果，候选未接入页面，Goal 进行中。

## 策略与规则边界

`teacher-v1` 原样调用当前 `chooseTeacherAction`；没有修改旧 `teacher.ts`、`advice.ts`、`teacherEvaluation.ts` 的排序或计算。`candidate-v2` 是显式候选，保留相同开局，修正没有合法等待的“0向听”、补计公开自摸胡张，并试验按存活人数估算正常轮转的 0/1/2 摸预算和残局查叫价值。碰杠仍沿原动作比较，只更换其弃牌评价来源。正常轮转预算不模拟碰杠或玩家退出，不是实际摸牌机会的断言。

`ebony-initial` 采用 [ebony72/Mahjong 固定提交](https://github.com/ebony72/Mahjong/tree/2d46ffa0ba84f486c336935d8f3e105f4e39e5a2) 的 `strategy_initial21_7attr` 与 `daquex`。原始七文件及 MIT 许可逐字节保留在 [vendor 清单](../vendor/ebony72-mahjong/UPSTREAM.json)，SHA-256 闭包为 `ab085c0b203155dd8f9396ba01d2cf39cf92349b71d8ff6e10f18738450eabe9`。适配器启动时检查固定提交、文件哈希和闭包；未导入其引擎或高级 Oracle 策略。

全部策略在本项目 [V1 规则](RULES_V1.md) 中执行与结算。与上游环境不同的自摸加番、金钩钓、花猪支付、退税、呼叫转移等不带入本桌。初始策略并不完整优化这些计分差异，也没有高手水平认证。初始与后续可能接入的高级策略同源，不能把版本数当作独立高手标尺数量。

初始策略没有换三张，因此这里的“整套”实际是明确的组合策略：共用 `teacher-v1` 换三张，之后采用各自定缺与行牌。另有 `common` 模式让四家换牌和定缺都采用相同的老师开局，专门减少开局差异对行牌比较的掩盖。`composite` 与 `common` 分层报告；只有一个外部对手实现，`teacher-v1` 阵容只是内部敏感性对照，尚未满足多类独立对手验证。

## 信息与记录

- 引擎新增 `publicTiles`，记录当前未被认领的弃牌与自摸公开胡张的实际时序。碰杠认领移除对应弃牌；点胡不重复计牌；抢补杠成功记被抢牌一次。它不包含赢家其余暗牌。
- `PlayerView` 仍只含本家手牌及公开信息。Python 收不到种子、真实牌墙或对手暗牌；宿主在序列化前逐层检查允许字段。对手 `.hand`、墙索引和迭代在 Python 门面中直接报错。
- 库存按每种四张减本家手牌、全部公开面子和有序公开牌，不能再把逐座弃牌重复扣除。万/条/筒编码显式映射到上游条/万/筒。
- 每座位每局独立常驻 worker；会话首次绑定座位，不能读取别座暗牌。请求只有不含种子的序号。错误、超时、非法动作、来源不符或协议污染均失败，没有内部策略回退。成功收尾必须发送 EOF、排空回复并确认正常退出，最后一个有效动作不能掩盖其后的进程错误。
- `transfers` 只记录实际积分转账，按自摸、点胡、放铳、支付别人自摸、杠钱、花猪、查叫分类。每次状态转换检查 108 张和积分零和，每家的分类净额也必须等于终局净分。

完整对局决策视图与动作保存到 `traces.jsonl`；失败保存已执行决策和当时请求。它们是合成牌局数据，保存在忽略的 `local/` 内。只有一个种子的全部座位、阵容、开局和策略组合完成后，才向 `games.jsonl` 追加该种子结果。崩溃后未提交的种子整组重跑，原 trace 可能含同配置的重复尝试；成绩以 `games.jsonl` 的已校验完整种子为准。

## 运行与复现

需要 Node 22、`npm ci` 和 Python 3.10+。Python 仅用标准库；这不是网页运行依赖。可用 `STRENGTH_PYTHON` 指定解释器。先保存显式 JSON 配置，例如：

```json
{
  "mode": "development",
  "seeds": [80000, 80001, 80002, 80003, 80004, 80005, 80006, 80007],
  "seats": [0, 1, 2, 3],
  "lineups": ["ebony-initial", "teacher-v1"],
  "openings": ["common", "composite"],
  "policies": ["teacher-v1", "candidate-v2", "ebony-initial"],
  "comparisons": [
    { "candidate": "candidate-v2", "baseline": "teacher-v1" },
    { "candidate": "ebony-initial", "baseline": "teacher-v1" }
  ],
  "timeoutMs": 10000
}
```

```powershell
npm run evaluate:independent -- local/strength-goal-20261018/development-v2.config.json local/strength-goal-20261018/development-v2
python -B -m unittest discover -s scripts/external -p test_worker.py -v
npm run check
```

输出放在 `local/` 等源码目录之外，不能放入 `scripts/` 或 vendor。`games.jsonl` 首行冻结配置、V1 规则、执行源码、vendor、包锁、Vite/TypeScript 配置的哈希及 Node/Python 版本；续跑必须逐项一致，运行中变更源码也会拒绝提交当前种子。并发写入由可核查 PID 的锁阻止。截断或损坏的成绩文件保留原字节并报错，需要先排查。`summary.json` 明示已完成种子与是否完整。

同一种子的共享内容是初始洗牌与环境；动作分歧后摸牌接收者会变，不能声称全程摸到相同牌。统计先在每个种子内等权平均指定座位、阵容和开局，再跨种子计算配对均值、标准误和 95% 正态近似区间；另列开局、阵容及交叉分层。小样本区间只作诊断，不自动判定通过，也不能反复挑选显著的分组。

### 后续单次暗杠干预：没有支持直接放宽门槛

进一步只读扫描旧策略轨迹，受评本家有 1225 个弃牌节点、173 个可碰响应、62 个可杠节点。四副露一暗牌威胁只出现 4 个本家节点，且均只能打一种合法牌，所以单独增加这种风险模型仍不能改变这批动作。近听时穷举原模型全部同向听候选，发现 3 个 top-3 截断漏优配置，其实来自 `80002/seat1/step10` 同一个起手；这只证明模型截断，不能把稍高模型收入当真实最优动作。

拒绝暗杠的 24 个配置节点全部来自 `80004`，对应 10 个公开 view 簇。诊断先精确复现 8 个原配置的全部动作和终局，再逐配置只强制目标那一次合法暗杠，之后恢复 `teacher-v1`。24/24 目标公开节点与干预前轨迹精确匹配，worker 均正常收尾，逐项收入差与净分差一致，执行前后源码哈希一致。

结果是 8 次改善、4 次不变、12 次变差，净分差范围 [-3,+7]。它们高度相关、只有一个 seed 簇，不计算置信区间，也不把 24 个节点当独立样本。早期 `step10` 强制暗杠的相对净分差为 0，基线后来本来也会杠；`step18` 的 +7 来自自摸收入 +9 与点胡收入 -2，最终杠钱差仍为 0。另一些节点多收 2 分杠钱，却少 3 分自摸并多付 2 分别人自摸，最终净差 -3。**不能把即时杠钱直接当作相对“先出牌”的额外收入，也不据此放宽暗杠向听门槛。**

[诊断报告](../local/strength-goal-20261018/kong-diagnosis/run-4/report.md)、完整公开节点和收益在同目录 `outcomes.jsonl`，全部干预动作在 `counterfactual-traces.jsonl`；脚本为父目录 `diagnose-kong.ts`。`run-1..3` 是未完成的脚本预检，不计入结果。真实牌墙下的单次反事实只用于开发诊断，不能把有利节点反写成最优动作标签。

## 下一次继续的实现方向

以下是 V2 结束时的实现计划；其中公开历史、高级派生版和自杠配对续局现已完成接入及工程验证，实际范围与仍未完成的强度验证见 [V3 记录](INDEPENDENT_BENCHMARK_V3.md)。

1. 为外部高级公有策略补齐**真实完整公开动作流**，包括不带牌的摸牌、全部弃牌（认领后仍保留）、碰、直/暗杠、补杠提议和公开胡牌。现有 `publicTiles` 只是剩余桌面牌，不能替代这段历史。补杠提议记一次，被抢后不补造成功事件；庄家初始 14 张不能伪造额外摸牌。
2. 固定上游 `strategyz0614.py` 的明确派生版本，建议 ID `ebony72-advanced-public-v1`。只读审核定位到 688–690 行无条件读取对手 `.hand` 并计算 `GPhi`，其唯一有效消费在 697–698 的 Oracle 分支；派生版需删除整段暗牌读取和启用分支，不能给对手填假手牌。保留完整选牌入口的七对/清一色分支。高级策略和依赖尚未 vendoring、未执行、未注册，也没有实力结论。
3. 高级公有门面还需本家 `get_dominant_color`、`get_pure_color_index`、合法杠候选，以及 dealer 的 `numWl/n_hu/dqc/guess_color_distribution`。后者使用 `xzdealer.py:138–174` 和 65–134 的动作更新；必须用真实公开流，不能倒拼已认领弃牌。换三张后的固定先验、自摸倍数与不封顶等上游估值差异需要明确披露，后续仍在宿主 V1 中结算。
4. 候选方向改为在**同一组只由公开信息生成的采样局面**上，配对比较“现在杠”和“先打牌”的续局，保留以后开杠的可能。真实隐藏牌墙只能用于开发诊断，不能传入生产策略或用它给每节点挑动作。采样约束、近似对手、续局深度、计算成本和解释都要明确，先用新代表性测试证明合法性与信息隔离，再以开发组检验是否真的改变常见动作并提高净分。
