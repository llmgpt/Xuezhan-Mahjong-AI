# 合理老师：实现与验收协议

> 2026-10-14，在新老师策略定稿和正式评估前确定。目标是合理、可解释且有实测收益的教学策略；正式结论以保存的结果为准。

## 交付范围

覆盖换三张、定缺、出牌、碰杠胡。策略只接收 `PlayerView`，解释来自本次实际使用的比较指标。先采用规则和有限搜索，不从零训练模型。

策略参考 [Sichuan Mahjong 策略仓库](https://github.com/ebony72/Mahjong)的“成牌距离、可用牌、公开信息”思路，以及 [缺牌数算法论文](https://arxiv.org/abs/2108.06832)。移植须适配本桌七对、缺门、番数封顶和自摸加底；外部仓库的自摸偏好或收益阈值不直接照搬，任何 oracle/对手真实手牌代码不得进入老师输入。本文不把简化模型中的最优性外推为完整血战最优。

## 先冻结，再测留出集

- 开发阶段：种子 60000～60039，用于找错误、比较候选和调整；此前看过或启动过评估的种子也只算开发材料。
- 正式留出：第一组预定 70000～70199，共 200 个种子。定稿后记录全部规则、引擎、策略及评估代码的 SHA256，再开始运行。
- 为缩短运行时间，预定等分为 70000～70049、70050～70099、70100～70149、70150～70199 四个 50 种子分片并行。所有分片共用相同冻结源码和其他配置；全部完成后从 200 个原始种子一次重算统计，不平均分片区间，不根据分片成绩取舍。
- 若看过这组结果后修改策略，该组转为开发材料；下一次正式评估必须预先记录新的未用种子区段。不通过反复查看同一留出组调参来宣称有效。
- 不根据途中成绩改变样本量、对手、计分、权重或主指标。技术中断可按相同 manifest 续跑；不匹配的结果不能混用。

## 比较对象与配对条件

基线一是当前完整建议 `advice`；基线二是 `efficiency`，仅将出牌改为向听→有效进张→固定牌序，其余决策保持原策略。基线调用链保持原行为，不能随新老师一起升级。

每个种子让老师和基线分别控制 0～3 号座位，另外三家分别使用两类冻结对手：`greedy` 为原电脑的优先胡杠碰；`patient` 按原动作建议决定碰杠，并以简化牌效出牌。两个对手环境等权。它们不是高手模型，结果只表明对这两类对手的表现。

同种子、同座位、同规则、同对手组成一对；只保证初始牌墙相同，选择分叉后的摸牌和响应轨迹会不同。庄家仍固定为 0 号。称“同初始牌墙、跨座位配对”，不称赛事的完整 duplicate 赛制。

必须另测 `teacher-legacy-discard`：将老师的**出牌推荐模块**回退原策略，换牌、定缺和响应窗口逻辑保持相同。自杠比较中的“不杠”弃牌基准也来自这个模块，因此它可能随回退改变；这不是严格固定全部非出牌动作的单张弃牌消融。这项对照检查开局收益是否掩盖新出牌模块的退步；差值包含这些耦合与后续整局轨迹，不能当作单次出牌的真实价值。

## 主指标和通过条件

主指标是终局净分。先对每个种子的四座位、两类对手等权取配对净分差，再以 **200 个种子**估计标准误和正态近似 95% 区间。不是把 1600 个相关局面当作独立样本。另报各对手、各座位结果。

第一版宣称“在内部 benchmark 中有效”须满足：

1. 完整老师相对 `advice` 和 `efficiency` 的主配对净分差，95% 区间下界均大于 0。
2. 两类对手下的点估计方向均为正，完整列出各自区间；不能靠一类对手的大幅收益掩盖另一类的平均退步。
3. 相对 `teacher-legacy-discard` 的新出牌消融，配对差区间下界大于 -0.25 分/局。0.25 是运行前规定的阶段容差；整套老师仍须满足前两项正增益条件。若新出牌达不到这项要求，回退或改进后重测。
4. 所有配置的牌局完成，无非法操作、超步数或静默丢样本；108 张牌和积分零和保持。
5. 规则事实牌例、公开信息隔离、建议与实际排序依据一致的测试通过，并完成本地整局试玩。

交付调整（2026-10-17，正式评估之后）：用户决定跳过代理端浏览器整局试玩，改由用户直接试玩验收。本次开发交付不再以该步骤为前置条件；第 5 项中的真实界面体验仍未验证，不记为通过。上述预定策略强度条件、冻结代码和留出样本不作调整，不能把这次产品验收范围变化用于扩大 benchmark 结论。

胡牌占比、流局占比、点炮损失和杠钱等是解释指标，不替代主净分。区间跨零或跨阶段容差时，结论写“尚未分出/尚未确认”，不能用不显著推断没有退步。样本报告及完整结果与失败情况一并保存。

## 教学结论的边界

真实/公开牌例用于检查明显策略错误、规则差异和解释事实；仅凭一局输赢不评价策略强弱。内部净分增益支持这套策略在规定环境中的有效性，不证明每手唯一最优，也不直接证明玩家学习效果。后者仍由用户试玩验收及后续未见牌例的理解测试检查。
