# 实际牌桌电脑的内部对照

> 更新于 2026-10-19。新增离线策略 `ui-greedy-v1` 和阵容 `ui-bots`，与当前页面电脑的规则对齐。两旧种子、四座位共8组完整配置核对通过；当前全部工程检查39文件339项测试通过。页面策略与默认建议未改，产品环境强度评测尚未完成。

页面本家建议/托管使用老师，而三名电脑由 [session.ts](../src/game/session.ts) 驱动：先收合法胡，响应依次杠、碰、过；自杠先补杠后暗杠；否则取旧 `recommendDiscards` 第一项。电脑开局在 [demo.ts](../src/game/demo.ts) 使用 [bot.ts](../src/game/bot.ts) 的原换牌和最少张数定缺。这与 `teacher-v1` 四座向量不同，老师互打只能作为内部敏感性环境，不能自动代表实际页面电脑。

离线已有 `chooseOpponentAction(...,"greedy")` 恰好使用这些开局与行牌选择，现直接复用并注册 `ui-greedy-v1`，无需 Python。它明确是项目内部策略，与老师共享部分建议实现；`ui-bots` 不算第三种独立外部来源，也不能单独承担高手标尺。

[注册测试](../scripts/independentPolicies.test.ts)先因未知 ID 失败，接入后核对换牌、定缺、出牌、输入不变、会话收尾及不启动外部 worker。[完整对齐测试](../scripts/uiOpponentParity.test.ts)用已使用的 `80000,80007`：在每个受评座位，本家按实际托管选择，其他座位由页面的 `completeExchange`、`completeMissing`、`advanceToHuman` 执行；另从独立执行器运行相同配置。8组配置各运行两个完整局，最终整个 `GameState` 逐字段一致，包括牌墙、手牌、面子、公开日志、胡牌、分数和转账；离线每步及自动摸牌另核对108张和step，终局收入一致。

这验证当前冻结代码的完整终局对齐，不是浏览器点击测试、全部中间 UI 状态逐点比较或策略强度结论。页面目前固定本家0号；四座位是对同一组游戏函数的离线泛化检查，没有新增页面换座功能。有效自行动作必有缺门与合法弃牌，因此旧推荐非空，页面的异常空推荐兜底不会在这些合法节点生效。

产品环境对照已在结果产生前冻结并启动，见[协议](benchmarks/ui-development-v1-protocol.json)。采用 `ui-bots`，保留共同/组合两开局：共同开局统一老师，隔离中后期；组合开局让三电脑沿用原开局，才与当前默认托管的完整产品环境一致。T/D本家都用老师开局。源码为7b6993a的101项原字节快照，40旧开发seed（60000..60039）×四座位×两开局×T/D，共640局、320配对、40个种子统计单位；不是新的正式留出。全部完成前不看部分强度成绩，报告全部/开局/座位面板的种子聚类均值与1.96标准误近似区间，没有事后通过门槛。真实句柄与输出路径见忽略目录 `local/strength-goal-20261018/ui-development-v1-execution.json`。

完整结果和原始动作审计后，再决定候选及正式产品环境通过条件；不能以只在另一类对手中较好为由直接替换页面默认策略。两作者外部对照和原高级整套策略仍保留在各自冻结实验中。
