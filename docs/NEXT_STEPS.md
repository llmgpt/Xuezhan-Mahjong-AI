# 新对话开发交接

> 更新于 2026-09-29。这里记录下一步工作；实际完成情况以仓库文件和测试结果为准。每完成一个里程碑，更新本页并移除过期任务。

## 当前状态

- 项目是面向学习的四川血战到底网页游戏，公开仓库为 [llmgpt/Xuezhan-Mahjong-AI](https://github.com/llmgpt/Xuezhan-Mahjong-AI)。
- 仓库目前只有规划文档；游戏、规则引擎、测试、CI 和可访问网页都尚未实现。
- 第一阶段技术栈已选定为 **TypeScript + React + Vite**，先在浏览器内运行；账号、后端和数据库没有进入第一阶段。
- 首个可玩目标是玩家与三名电脑对手完成一局，并在出牌时看到推荐牌、至少一个备选及理由。复盘和 AI 观战排在之后。
- 已安装的开发 skill 和 Serena MCP 是个人开发工具，不是游戏运行依赖。

## 已确定的设计边界

- 规则判定、对局流程、建议策略和页面展示分开。地区或平台规则差异要显式记录，不能藏在代码假设中。
- 玩家模式的建议只能使用自己的手牌和公开信息；观战若显示全部手牌，要标明教学视角。
- 初版建议可以采用可解释的启发式或搜索策略，说明向听、有效进张、收益、风险及尚未考虑的因素；不要称其为训练过的 AI。
- 随机发牌和电脑对局支持固定种子，方便重现测试、问题和复盘。

上述决定的详细依据见 [项目计划](PROJECT_PLAN.md)、[架构草图](../ARCHITECTURE.md)和[开发与反馈回路](ENGINEERING.md)。

## 下一项开发任务

**固定第一版规则并建立最小代码与测试反馈回路，然后实现第一个可验证的对局切片。**

1. 新建 `docs/RULES_V1.md`，把常见血战到底玩法落实为明确的第一版规则：换三张、定缺、庄家与摸打顺序、碰杠胡及操作优先级、胡牌后继续、牌墙耗尽、番型与计分、查叫和查花猪。对存在差异的条目写明本版选择及可配置方向；没有偏好时采用明确的默认值并记录依据。
2. 准备少量代表性固定牌例与回合场景，覆盖合法操作、胡牌、牌数守恒和血战结束条件。规则、计分、流程与建议算法按先失败测试、后实现的顺序推进。
3. 建立 TypeScript、React、Vite 项目，以及锁文件、格式检查、静态检查、测试、生产构建和 CI；把实际运行命令写入仓库文档。
4. 先实现牌表示、带种子的洗牌与发牌、对局状态和第一批合法动作。保持规则引擎可独立测试，再接页面和电脑对手，逐步达到首个可玩目标。

第一轮工作完成时，应能从干净检出运行检查，并用固定牌例证明已实现的规则行为；文档要明确哪些玩法已支持、哪些尚未支持。不要把后续里程碑提前标成完成。

## 新对话怎么开始

在这个项目目录开启新对话，直接说“按 `docs/NEXT_STEPS.md` 开始开发”即可。新对话先核对仓库现状和相关文档；本页提供交接，不替代实际代码、测试和规则文档。
