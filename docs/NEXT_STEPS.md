3. 用更多真实对局和固定种子核对地区规则差异，尤其查叫的实际可用牌定义、复杂抢杠和杠钱。发现差异先更新 [规则表](RULES_V1.md)，规则、计分、流程或建议行为变更先写失败测试。
4. 将本地浏览器整局操作检查纳入自动化，覆盖开局、响应、建议、结算及窄屏布局；CI 目前只有单元牌例、静态检查和构建。已打通内置浏览器的本地试玩，按实际改动使用，不再把 Windows 浏览器连接排查作为开发前置。
5. 若以后增加牌谱保存/导出，明确规则与策略版本并保留每次决策时**当时可见**的信息，回放不能用后续牌面解释旧决策。
6. 公开网页部署在验收后进行。

建议的向听、进张、收益和风险目前是粗估；有缺门牌时页面暂缓报告向听。不要把这些数字描述为精确获胜率或放铳概率。模块边界见 [架构草图](../ARCHITECTURE.md)，开发验证流程见 [开发与反馈回路](ENGINEERING.md)。

## 新对话怎么开始

在项目目录开启新对话，说明要核对的规则牌例或当前建议范围即可；先核对仓库现状与相关文档。本页提供交接，不替代实际代码、测试和规则文档。
