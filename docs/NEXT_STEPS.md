# 新对话开发交接

> 更新于 2026-09-29。这里记录下一步工作；实际完成情况以仓库文件和测试结果为准。

## 当前状态

- 项目是面向学习的四川血战到底网页游戏，公开仓库为 [llmgpt/Xuezhan-Mahjong-AI](https://github.com/llmgpt/Xuezhan-Mahjong-AI)。
- 已有 [第一版规则目标](RULES_V1.md)、TypeScript + React + Vite 脚手架、锁文件、CI 和固定牌例测试。浏览器页面是换牌、定缺、摸打的**规则切片演示**，不是完整游戏。
- 已实现牌表示、种子洗牌发牌、顺时针换三张、定缺和强制缺门出牌；纯规则函数可判定标准型/七对胡牌与血战结束条件。碰杠胡响应、计分、流局结算与可解释建议尚未接入。
- 首个可玩目标是玩家与三名电脑对手完成一局，并在出牌时看到推荐牌、至少一个备选及理由。复盘和 AI 观战排在之后。
- 已安装的开发 skill 和 Serena MCP 是个人开发工具，不是游戏运行依赖。

## 已确定的设计边界

- 规则判定、对局流程、建议策略和页面展示分开。地区或平台规则差异要显式记录，不能藏在代码假设中。
- 玩家模式的建议只能使用自己的手牌和公开信息；观战若显示全部手牌，要标明教学视角。
- 初版建议可以采用可解释的启发式或搜索策略，说明向听、有效进张、收益、风险及尚未考虑的因素；不要称其为训练过的 AI。
- 随机发牌和电脑对局支持固定种子，方便重现测试、问题和复盘。

上述决定的详细依据见 [项目计划](PROJECT_PLAN.md)、[架构草图](../ARCHITECTURE.md)和[开发与反馈回路](ENGINEERING.md)。

## 下一项开发任务

**在现有可验证切片上实现完整的碰、杠、胡响应与血战流程，随后实现计分和建议。**

1. 用固定牌例先写失败测试，再接入弃牌响应窗口：多人胡、胡优先于杠碰、最近座位优先；实现碰、直杠、暗杠、补杠、补牌和抢杠胡。保留 108 张牌数守恒。
2. 让胡牌玩家退出摸打并继续血战；三家胡或墙尽后正确结束。将独立胡牌结构判定接入动作流程，并覆盖定缺门牌、七对和多家胡。
3. 接入 [规则表](RULES_V1.md) 的番型、支付、杠钱、查叫与查花猪；记录积分守恒。对差异规则使用显式配置。
4. 再实现玩家模式受限视图、可解释出牌建议与基础电脑策略，使玩家能与三名电脑完成一局。届时加入浏览器关键流程检查。

当前第一切片可通过 `npm ci && npm run check` 验证；代表性牌例覆盖发牌、换牌、合法出牌、胡牌结构与结束条件。后续每项规则行为仍按先失败测试再实现。不要把当前演示标成完整可玩版本。

## 新对话怎么开始

在这个项目目录开启新对话，直接说“按 `docs/NEXT_STEPS.md` 开始开发”即可。新对话先核对仓库现状和相关文档；本页提供交接，不替代实际代码、测试和规则文档。
