# 血战麻将学习项目：第一版计划

## 已确定的方向

- 形式：浏览器网页游戏。
- 发布：使用公开仓库 [llmgpt/Xuezhan-Mahjong-AI](https://github.com/llmgpt/Xuezhan-Mahjong-AI) 保存项目文档和后续代码；网页可用后再部署可访问版本。
- 玩法基准：常见四川血战到底；具体规则在实现前固定并记录差异。
- 核心目标：通过自己打牌、获得解释清楚的建议、观看 AI 对战和复盘来提高技术。

## 第一版要做到什么

1. 玩家能与三名电脑对手完成一局，页面明确显示当前阶段、可执行操作和公开牌面。
2. 每次需要出牌时，显示推荐牌及至少一个备选，并解释判断依据。
3. 玩家可以查看本局关键决策：当时手牌、实际出牌、系统推荐和差异说明。
4. 可以观看四名电脑对手对战，逐步播放或暂停，并查看每步选择的理由。

建议系统在玩家模式下只使用玩家手牌和公开信息。观战时若展示所有手牌，应明确标记为教学视角。初版可使用可解释的规则与搜索算法；是否加入模型训练或外部 AI 服务，以效果验证结果决定。

## 开发前需要固定的规则

| 主题 | 要确认的内容 |
| --- | --- |
| 开局 | 庄家、换三张的顺序和交换方向、定缺时机 |
| 行牌 | 摸打顺序、碰杠条件、抢杠与补牌、多人可胡的处理 |
| 胡牌 | 自摸与点炮、胡牌后其余玩家继续的流程、牌墙耗尽条件 |
| 计分 | 番型、封顶、杠钱、呼叫转移等选用规则 |
| 结束 | 血战结束、查叫、查花猪和最终结算 |

这些内容先形成一份明确的规则表，再据此实现规则引擎。地区或平台之间存在差异的项目应做成配置，不在代码中隐含假设。

## 建议如何评价

出牌建议至少分开考虑：牌效率（向听和有效进张）、预计收益、点炮风险。每条建议应显示使用了哪些公开信息、为什么推荐、哪些因素还没有纳入计算。避免只给出一个看似精确的分数。

验证时准备一组固定牌例检查规则和建议，并用大量可复现的电脑对局比较策略表现。复盘中应能重现当时的信息范围，避免用后来才出现的牌解释先前选择。

## 实施顺序

1. 固定规则表和代表性牌例。
2. 实现独立、可测试的规则引擎。
3. 做玩家对战与基础电脑对手。
4. 加入可解释的出牌建议和复盘。
5. 加入 AI 观战和逐步讲解。
6. 开发过程中持续推送公开 GitHub 仓库；验收后部署网页。

当前文档是计划，不代表上述功能已经实现。
