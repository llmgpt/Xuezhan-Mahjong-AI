# 血战麻将学习项目：第一版计划

## 已确定的方向

- 形式：浏览器网页游戏。
- 发布：使用公开仓库 [llmgpt/Xuezhan-Mahjong-AI](https://github.com/llmgpt/Xuezhan-Mahjong-AI) 保存项目文档和后续代码；网页可用后再部署可访问版本。
- 玩法基准：常见四川血战到底；具体规则在实现前固定并记录差异。
- 核心目标：通过自己打牌或托管本家操作，边看当前牌局边理解建议来提高技术。
- 当前优先级（2026-10-18）：先提高同一套 V1 规则下的实战策略水平，以独立对照中的长期平均净分为主要验收指标，目标是经得起检验的较高水平。原因说明展示实际决策依据，随策略改进同步更新。

## 交付里程碑

首个可玩版本：

1. 玩家能与三名电脑对手完成一局，页面明确显示当前阶段、可执行操作和公开牌面。
2. 每次需要出牌时，显示推荐牌及至少一个备选，并解释判断依据。

策略强度与原因展示：

1. 玩家可暂停本家托管，在当步查看建议、备选、依据和简化两摸比较。
2. 用真实牌例定位决策问题，用独立参考策略和可复现的电脑对局验证策略强度；解释忠实展示选择依据与局限。

建议系统只使用玩家手牌和公开信息。初版可使用可解释的规则与搜索算法；是否加入模型训练或外部 AI 服务，以效果验证结果决定。

## 第一版已固定的规则目标

| 主题 | 要确认的内容                                       |
| ---- | -------------------------------------------------- |
| 开局 | 庄家、换三张的顺序和交换方向、定缺时机             |
| 行牌 | 摸打顺序、碰杠条件、抢杠与补牌、多人可胡的处理     |
| 胡牌 | 自摸与点炮、胡牌后其余玩家继续的流程、牌墙耗尽条件 |
| 计分 | 番型、封顶、杠钱、呼叫转移等选用规则               |
| 结束 | 血战结束、查叫、查花猪和最终结算                   |

上述主题已在 [规则表](RULES_V1.md) 中作第一版选择，并接入本地可试玩 V1。部分地区差异可在代码配置中切换，其余仍需独立开关与牌例。

## 建议如何评价

策略验收以相同规则下的长期平均净分为主，同时披露胡牌收入、点炮损失、杠钱和流局结算等来源。采用独立对手、轮换座位和未参与调参的种子；另以相同合理开局比较出牌与碰杠，避免开局优势掩盖中后期问题。战胜内部弱基线只能说明相对改善，达到较高水平仍需有实力依据的外部标尺。

出牌建议至少分开考虑：牌效率（向听和有效进张）、预计收益、点炮风险。每条建议应显示实际使用的公开信息和排序依据，说明哪些因素还没有纳入计算。规则总结、真实牌局分析、搜索或模型训练都是提升实战决策的候选手段，以独立对照结果决定取舍；教学课程、题库规模和学习前后测不作为当前策略交付的前置条件。

验证时准备一组固定牌例检查规则和建议，并用大量可复现的电脑对局比较策略表现。即时解释只读取当时可见的信息，不能用后来才出现的牌解释先前选择。当前第一组内部模拟对照和局限见[建议效果评估](ADVICE_EVALUATION.md)。

## 实施顺序

1. 固定规则表和代表性牌例。
2. 实现独立、可测试的规则引擎。
3. 做玩家对战与基础电脑对手。
4. 加入可解释的出牌建议和玩家自动托管。
5. 优先提高策略强度：接入独立参考、定位出牌与碰杠的薄弱环节，按实际牌例和冻结的留出对局验收；同步显示真实决策原因。
6. 开发过程中用聚焦的本地提交保存进度；推送、合并公开 GitHub 仓库及验收后部署网页，需要当前任务的明确授权。

当前已完成玩家对战、可解释建议和玩家自动托管；本局决策复盘与独立四电脑教学观战已按需求移除。真实牌例持续验收、自动浏览器 CI 和公开网页部署仍待完成。操作与信息边界见 [自动托管与实时建议](AUTOPLAY.md)，实际状态见 [README](../README.md)。

阶段性技术选择与模块边界见 [ARCHITECTURE.md](../ARCHITECTURE.md)；开发验证流程见 [ENGINEERING.md](ENGINEERING.md)。
