# 教学质量的独立验证

> 2026-10-17。用户不需要具备高手水平来判断老师是否正确。本次完成证据审计和外部对照候选初筛，尚未接入外部策略或运行新的正式评估。

## 当前证据能支持什么

| 方面               | 已有证据                                           | 仍缺什么                                             |
| ------------------ | -------------------------------------------------- | ---------------------------------------------------- |
| 规则与局部牌效事实 | 固定牌例、守恒和信息隔离测试；三项公开牌例事实核对 | 更多独立的完整局面；测试覆盖不能外推为全部策略正确   |
| 内部相对强度       | 预先冻结的 6400 局配对评估通过，两基线对照均为正   | 不共享当前决策实现的外部参考策略和更丰富的对手环境   |
| 教学建议质量       | 解释采用实际排序依据，并说明简化模型局限           | 对具体推荐及解释的独立核对，尤其出牌、碰杠和风险取舍 |

原 benchmark 的配对和按种子聚类统计结论保留，见[正式报告](TEACHER_REPORT.md)。证据缺口不能靠增加同一套配置的局数补齐：

- [benchmarkPolicies.ts](../scripts/benchmarkPolicies.ts) 中，`efficiency` 重排 `recommendDiscards`，`patient` 采用原动作建议和这套牌效排序，`greedy` 也使用原出牌建议；[teacher.ts](../src/game/teacher.ts) 从同一出牌候选起步。这些对照有行为差别，但可能共享实现偏差。
- [bot.ts](../src/game/bot.ts) 的旧换牌取固定花色顺序中第一门够三张的前三张。保留新开局、回退旧出牌仍增加 0.9019 分/局；完整老师相对回退版仅增加 0.0163，区间跨零。总收益不能替出牌教学质量背书。
- [公开牌例核对](ADVICE_CASE_AUDIT.md) 验证的是三项局部事实；争议路线和视频节点尚不构成完整、可独立裁决的策略验收集。

[Let's Play Mahjong!](https://arxiv.org/abs/1903.03294) 讨论有限换牌次数下提高成胡机会的策略，可用于设计局部模型核对；这种模型中的结论不等同于含点炮、计分和对手行动的完整血战最优策略。

## 下一轮最小有效验证

1. 先适配并审核一套外部参考策略，禁止复用当前向听、牌效排序或动作建议来冒充独立实现；只输入本家手牌及公开信息。用独立牌例和不可读取的暗牌字段检查适配正确性。非法决策须显式失败或披露，不能用静默回退掩盖。
2. 保留现有整套策略对照，另让老师与参考策略采用相同的合理开局，再比较出牌和碰杠，避免弱开局基线掩盖后续问题。先做开发组检查，再冻结实现、对手、规则、通过条件和新的未用留出种子，运行前另记协议；当前尚未运行新正式组。
3. 建立一小组状态完整、未用于调参的教学牌例。规则事实与听张用独立枚举核对；有取舍的策略采用可信详解或熟悉相同规则者的独立复核，允许多个合理候选。只有局面叙述不完整或缺乏依据时保留未判定，不能把真人某次出牌或另一大模型的答案直接当正确标签。

策略强度、规则事实和解释质量分别报告。失败或有分歧的牌例定位原因后再决定回退或改进，不用易懂的讲解替代正确性证据。

## 用户验收的职责

用户反馈是否听得懂、信息是否清楚、节奏和操作是否合适。策略质量由实现侧提供独立对照及可核验牌例来评价；用户看不出错误或没有异议，不作为教学正确性的通过证据。代理端浏览器整局试玩仍按用户决定跳过，这项体验范围调整不免除教学质量验证。
