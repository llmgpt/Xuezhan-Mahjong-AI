# 策略强度的独立验证

> 更新于 2026-10-18。当前优先提高实战策略水平，原因说明展示实际决策依据；用户不承担策略强弱的专业裁判。已接入固定来源的独立初始策略并开始开发组对照，尚未运行新的正式评估。接入边界、可复现命令与已知缺陷见 [V2 开发记录](INDEPENDENT_BENCHMARK_V2.md)。

主要目标是在同一套 V1 规则下提高长期平均净分，并通过有实力依据的外部标尺确认较高水平。普适牌理、真实牌局分析、搜索、模仿学习或强化学习均按实战收益与验证成本选择。完整局面用于诊断和回归；教学题库、课程和学习前后测不作为当前开发的前置要求。

## 当前证据能支持什么

| 方面               | 已有证据                                           | 仍缺什么                                               |
| ------------------ | -------------------------------------------------- | ------------------------------------------------------ |
| 规则与局部牌效事实 | 固定牌例、守恒和信息隔离测试；三项公开牌例事实核对 | 更多独立的完整局面；测试覆盖不能外推为全部策略正确     |
| 内部相对强度       | 预先冻结的 6400 局配对评估通过，两基线对照均为正   | 不共享当前决策实现的外部参考策略和更丰富的对手环境     |
| 具体决策的合理性   | 解释采用实际排序依据，并说明简化模型局限           | 独立核对出牌、碰杠和风险取舍，并定位影响净分的薄弱环节 |

原 benchmark 的配对和按种子聚类统计结论保留，见[正式报告](TEACHER_REPORT.md)。证据缺口不能靠增加同一套配置的局数补齐：

- [benchmarkPolicies.ts](../scripts/benchmarkPolicies.ts) 中，`efficiency` 重排 `recommendDiscards`，`patient` 采用原动作建议和这套牌效排序，`greedy` 也使用原出牌建议；[teacher.ts](../src/game/teacher.ts) 从同一出牌候选起步。这些对照有行为差别，但可能共享实现偏差。
- [bot.ts](../src/game/bot.ts) 的旧换牌取固定花色顺序中第一门够三张的前三张。保留新开局、回退旧出牌仍增加 0.9019 分/局；完整老师相对回退版仅增加 0.0163，区间跨零。总收益不能替出牌模块的独立增益背书。
- [公开牌例核对](ADVICE_CASE_AUDIT.md) 验证的是三项局部事实；争议路线和视频节点尚不构成完整、可独立裁决的策略验收集。

[Let's Play Mahjong!](https://arxiv.org/abs/1903.03294) 讨论有限换牌次数下提高成胡机会的策略，可用于设计局部模型核对；这种模型中的结论不等同于含点炮、计分和对手行动的完整血战最优策略。

## 下一轮最小有效验证

1. 先适配并审核一套外部参考策略，禁止复用当前向听、牌效排序或动作建议来冒充独立实现；只输入本家手牌及公开信息。用独立牌例和不可读取的暗牌字段检查适配正确性。非法决策须显式失败或披露，不能用静默回退掩盖。
2. 保留现有整套策略对照，另让老师与参考策略采用相同的合理开局，再比较出牌和碰杠，避免弱开局基线掩盖后续问题。先做开发组检查，再冻结实现、对手、规则、通过条件和新的未用留出种子，运行前另记协议；当前尚未运行新正式组。
3. 从对照中提取状态完整的分歧局面，定位攻守、收益、碰杠和残局决策的问题，形成开发回归牌例，并另留未用于调参的独立检查材料。规则事实与听张用独立枚举核对；有取舍的策略采用可信详解或熟悉相同规则者的独立复核，允许多个合理候选。局面不完整或缺乏依据时保留未判定，不能把真人某次出牌或另一大模型的答案直接当正确标签。无需先完成一定规模的教学题库才能推进策略对照。
4. 按薄弱环节改进候选策略，再在新的冻结留出组验证长期净分；同步报告胡牌收入、点炮损失、杠钱与流局结算，解释收益从何而来。是否扩大搜索或加入训练由实际验证结果决定，不能把方法名称或自博弈局数作为实力证明。

策略强度是当前主要验收目标，规则正确与公开信息隔离是必要条件。解释忠实展示实际计算与取舍，随策略同步更新；不把解释是否流畅作为决策强度证据。失败或有分歧的牌例定位原因后再决定回退或改进。

## 用户验收的职责

策略质量由实现侧提供独立对照及可核验牌例来评价；用户可以反馈原因是否清楚、节奏和操作是否合适，用户没有异议不作为策略正确的证据。2026-10-18 已在内置浏览器完成一局手动为主的试玩，覆盖部分托管与暂停；这验证页面流程，不替代策略强度评估。具体试玩范围见[当前交接](NEXT_STEPS.md)。
