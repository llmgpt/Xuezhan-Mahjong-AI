# 自动托管与实时建议

## 使用方式

- 牌桌底部的“自动托管”代替本家完成换三张、定缺、出牌及碰杠胡响应。三名电脑对手仍按玩家对局流程行牌。默认在每次本家决策前等待 **3 秒**，“牌局设置 → 托管节奏”可选 1、3、5 秒。
- 点击“暂停托管”可接管当前牌局；手动选牌或操作也会停止托管。打开设置或建议依据会暂停托管。
- 当前建议的简短原因显示在手牌上方；点击“查看依据”可看备选、取舍和局限。清完缺门后可按需比较两张候选弃牌在简化两摸模型中的表现。
- 打出万、条、筒时会中文报牌。换三张、定缺和清缺门只报结果；其他本家选择朗读该步的简短结论，偏离建议时提示推荐项。碰、杠、胡和结算有简短语音与提示音。完整依据可在当步“查看依据”弹窗主动朗读。托管等该步语音结束后再按所选节奏继续。三名电脑的公开动作也会报牌，连续动作只播最近几步。声音可在牌局设置中关闭，或选择并试听浏览器提供的中文声音；声音选择与开关保存在当前浏览器。没有语音支持时牌局仍可操作。

## 策略和解释边界

本家托管使用现有动作与出牌建议：优先合法胡牌，比较碰后的弃牌和未知补牌前的杠牌结构，按向听、进张粗估等选择出牌。换三张沿用简单基线：按万、条、筒顺序选第一门足够三张的花色，取该门手牌中的前三张；定缺选张数最少的一门，张数并列按上述顺序。本阶段没有训练模型；按需打开的两摸前瞻暂不改变托管和建议排序。其余三家的碰杠策略沿用原有规则。

策略与即时解释只使用本家手牌和公开信息，不读取对手暗牌或真实牌墙顺序。语音在本家行动时计算当步解释，不保存整局决策快照。响应选择可能等待其他人提交，申请碰杠不表示最终获得该面子。进张、收益、风险仍是启发式粗估，不表示精确概率。

两摸前瞻从本家视图扣除已见牌，枚举下一张可能摸到的牌；若不能直接胡，则在合法弃牌中选择两摸模型下成胡占比最高的延续。未见牌既可能在墙中，也可能在对手暗牌中；模型假设从未见牌均匀摸取，不处理对手在两次本家摸牌之间的弃牌、碰杠胡、点炮、番型和支付。显示的百分比只用于比较这个简化模型，不能当作真实胡牌率或净分预测。清缺门阶段与牌墙不足两张时不显示。

## 数据与验证

牌局状态和公开动作日志只保存在当前页面内存中，刷新或重新开局会清空。当前没有本局决策复盘、跨设备存储、牌谱导入导出或外部解析服务。

src/game/decision.test.ts 覆盖本家专属决策、托管到结算、108 张牌与积分零和、对手暗牌隔离及即时解释；src/game/lookahead.test.ts 覆盖前瞻的可见张数和清缺门边界。运行 npm run check 验证格式、静态检查、类型、单元测试和生产构建。自动浏览器 CI 仍待接入。
